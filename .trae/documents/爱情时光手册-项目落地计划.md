## 现状结论

* 当前仓库仅包含产品/架构文档，尚无前端/后端/AI集成的任何工程脚手架与入口文件。

## 目标（按MVP可运行优先）

* 在本机离线运行：导入多模态记忆（文本/图片/PDF）、自动抽取元数据与结构化信息、写入本地存储与向量库、支持自然语言检索并返回记忆卡片。

* 全程本地处理：不依赖云端服务；与本地 Ollama 模型对接。

* 隐私：敏感字段加密落盘（AES-256）。

## 仓库结构（建议单仓多应用）

* frontend/：React + TypeScript（Vite）

* backend/：FastAPI + Python（Pydantic Settings）

* shared/：可选（接口契约/示例数据/开发脚本）

* docs/：产品文档与接口文档

## 后端实现规划（FastAPI）

* 核心模块

* AI对话页面

  * 数据接入：文件上传（图片/PDF/文本）、文本记录创建、基础校验与去重（hash）。

  * 预处理：

    * 图片：EXIF/尺寸/时间；OCR（Tesseract 可选开关）。

    * PDF：文本提取（PyPDF2）；必要时 OCR。

    * 统一生成“记忆文档”标准结构：content、source、timestamps、attachments、raw\_text。

  * AI分析（分层可替换）：

    * MVP：优先用本地 LLM（Ollama）做结构化抽取（情感倾向、人物/地点/事件、标签、时间点）。

    * 增强：接入 Transformers 情感模型与 spaCy NER（作为可选 pipeline）。

  * 向量化与检索：

    * 使用 Chroma 持久化目录（本地磁盘），存 embeddings 与 document id。

    * Embedding 方案：优先使用 Ollama embeddings；若不可用则提供可配置备选。

  * 元数据存储：

    * SQLite（SQLModel/SQLAlchemy）保存记忆主表、标签、实体、附件索引、时间线索引。

  * 加密存储：

    * 使用 cryptography 实现 AES-256-GCM；仅加密敏感字段（例如原文片段/人物称谓等可配置）。

    * 密钥来源：环境变量/本地密钥文件（不入库），提供初始化与轮换命令。

* API 设计（MVP）

  * POST /memories：创建文本记忆

  * POST /uploads：上传文件并生成记忆

  * GET /memories：列表/过滤（时间、标签、人物）

  * GET /memories/{id}：详情

  * POST /search：自然语言检索（可返回相似度与摘要）

  * GET /health：检查 Ollama/Chroma/DB 状态

## 前端实现规划（React + TS）

* 页面

  * 记忆录入：文本输入 + 文件上传（拖拽）

  * 时间线：按日期聚合的卡片流（支持标签筛选）

  * 检索：自然语言搜索框 + 结果列表/详情抽屉

  * 设置：模型地址、加密状态、索引重建

* 交互

  * 上传进度与后台分析状态（轮询或 SSE）

  * 记忆卡片展示：摘要、标签、人物/地点、来源附件预览
